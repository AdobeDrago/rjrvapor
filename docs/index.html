Full parity ledger (import-work/ledger.md)

Baseline at start: no get_usage reading was taken at session start. At the end of the local build this session's context was 202k tokens. The extra-usage meter ($320.64 of $600 at that point) is account-wide and shared with parallel sessions, so this session's spend can't be separated out. Gate: ≥99% pixel and 0 computed-style mismatches per section at 1440 + 1280 (default bar, not lowered).

Font residual (accepted by the user before building): the source sets type in franklin-gothic-urw / franklin-gothic-urw-comp from Adobe Fonts (Typekit), and the EDS site has no licensed kit. The rebuild keeps the exact computed font-family strings and aliases those family names to local Arial / Arial Narrow faces (styles/styles.css). Their size-adjust comes from glyph widths measured on the source crops, and the ascent/descent overrides from measured baselines. The text still renders as Arial, so every section with text stays below 99% pixel, and the remaining style mismatches are glyph widths (x/width of inline text). Remove the alias faces when a kit is added.

Rules from the repo's AGENTS.md

  • Markup comes from the backend: fetch /path.plain.html before writing a block.
  • buildAutoBlocks rewrites content before a block runs; authors omit and add cells, so decorate defensively.
  • Scope CSS to .blockname; -wrapper and -container are section classes.
  • A PR without a {branch}--rjrvapor--AdobeDrago.aem.page/{path} link is rejected.
  • Merging main ships code; content is previewed and published separately in DA.
  • All committed files are served — use .hlxignore for anything that should not be.

Authoring workflow in DA.live

  1. Open da.live/#/adobedrago/rjrvapor and edit the document.
  2. Preview from DA (or use the Sidekick) and check https://main--rjrvapor--adobedrago.aem.page/.
  3. For a code change, branch from main, push, and open the PR with the <branch>--rjrvapor--adobedrago.aem.page link.
  4. Publish content to .aem.live after QA.
